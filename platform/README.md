# Локальная платформа Qazaq Loc QA

Откройте http://127.0.0.1:8090 после запуска `start-platform.cmd` в корне проекта. Для остановки используйте `stop-platform.cmd`. Qwen работает отдельно на порту 8088: её можно запустить кнопкой в левой панели или через start-qwen.cmd; остановка модели — stop-qwen.cmd.

## Что можно увидеть

- **Обзор:** структурные проблемы, кандидаты, неопределённые ответы модели, текущий журнал, прогресс по строкам и раскрываемая таблица покрытия всех 11 модулей.
- **Строки перевода:** поиск по ключу и тексту, сравнение RU/KK, английский контекст, выбор строк для точечного запуска.
- **Проверки:** независимое включение 8 кодовых и 3 языковых модулей, выбор всех или отмеченных строк, общий лимит запросов Qwen.
- **История:** завершённые, остановленные и прерванные запуски, повторное открытие отчётов, сохранение настроек.
- **Подробности находки:** объяснение, связанные ключи, ручное подтверждение или отметка ложной тревоги с комментарием. Это проверка находки, не утверждение нового перевода.
- **Ответы Qwen:** цитаты, объяснение, время, использование кэша, исходный ответ и причина перевода в uncertain.
- **Экспорт:** JSON и HTML с текущими отметками проверки. Никаких автоматических изменений ARB.

## Рекомендации с подтверждением человека

### Имена и названия без глоссария

В разделе «Возможно, перевод не требуется» собираются подсказки по ключам и форме текста. Они не гарантируют распознавание всех имён и не скрывают находки. Откройте любую находку `same_as_source`, при необходимости нажмите «Определить тип с Qwen». Этот отдельный запрос (до 240 секунд) классифицирует весь текст как имя, бренд, город, страну или неизвестное; его результат не является одобрением. Запрос выполняется по кнопке, не для всех 280 совпадений автоматически.

Выберите тип, укажите имя проверяющего и причину, затем подтвердите, что именно эту строку переводить не требуется. В следующем запуске платформы совпадение RU/KK будет пропущено для точного набора, ключа, исходника, перевода и контекста. Плейсхолдеры, ICU и прочие проверки не отключаются. Городам и странам могут требоваться казахские названия: нельзя автоматически разрешать совпадение по одному типу сущности.

Решения сохраняются в `platform/private-data/entity-exceptions.json`, переживают перезапуск и отменяются из карточки или списка исключений. Старые отчёты не переписываются. Изменение исключений во время анализа действует со следующего запуска. JSON/HTML показывает применённые исключения в `suppressed_findings`. Имя проверяющего вводится пользователем, это не авторизованная учётная запись. CLI может использовать аналогичный список в `config.entity_exceptions`; автоматически локальную базу платформы CLI не читает.

Тесты: `node --test platform/entities.test.mjs platform/server.test.mjs platform/recommendations.test.mjs`. Проверяется распознавание формата ответа на подставном транспорте, явное согласие, сохранение/отмена, возврат проверки при изменении текста или контекста. Эти тесты не измеряют точность распознавания имён живой Qwen.

В карточке рекомендации можно изменить текст, указать имя проверяющего и комментарий, затем нажать «Сохранить правку для проверки». Сохранение всегда возвращает предложение в ожидание решения, в том числе после прежнего одобрения. Затем нажмите «Подтвердить это исправление»: подтверждается именно сохранённая версия. Несохранённые изменения, устаревшая карточка, пустое имя или нарушение структуры блокируют подтверждение. Имя вводится пользователем и не является проверенной учётной записью. История версий и решений хранится в `corrections[].history` (фактически corrections — объект по ID находки).

После скачивания файла проверьте его установленным Flutter SDK из корня проекта:

```powershell
.\verify-flutter.ps1 -Source .\basw\handout\intl_ru.arb -Target C:\path\intl_kk_fixed.arb
```

Скрипт создаёт отдельный проект в `platform/private-data`, копирует оба файла, запускает `flutter pub get` и `flutter gen-l10n`, проверяет наличие результата. Исходники не изменяются. Для первого запуска Flutter могут потребоваться сеть и загрузка зависимостей. Без Flutter в PATH скрипт завершается ошибкой, а не сообщает об успешной проверке. Настройки ICU конкретной игры при необходимости нужно повторить в её Flutter-проекте.

Откройте находку и нажмите «Предложить исправление». Qwen выдаст полный вариант перевода и объяснение либо сообщит, что уверенной рекомендации нет. Генерация на CPU может занять несколько минут (до двух попыток по 240 секунд). Пока она выполняется, новый анализ или другая генерация не запускается. Ошибочный ответ не создаёт предложение.

Предложение сохраняется со статусом «Ожидает вашего решения». «Подтвердить находку» не подтверждает исправление: для этого есть отдельная кнопка «Подтвердить это исправление». Можно отклонить предложение или отменить подтверждение. Решения сохраняются после перезапуска, модель не может их выставлять.

После подтверждения доступен `intl_kk_fixed.arb` — отдельный файл только с одобренными исправлениями текущего запуска. Исходный ARB не меняется. Метаданные исправленных ключей сохраняются и дополняются `reviewed_by_human: true`. Подстановки, ICU и HTML-теги проверяются повторно на сервере. Дубликаты исправляемого ключа или его метаданных блокируют подтверждение: их нужно сначала разрешить в новом наборе. Изменение исходных данных тоже требует нового запуска. У несвязанных ключей дубликаты и комментарии сохраняются.

Проверка структуры не гарантирует правильность казахского текста. Экспорт ещё необходимо проверить в целевом Flutter-проекте через `flutter gen-l10n`. Здесь Flutter-проект не запускался. История предложений текущего состояния доступна в JSON-отчёте (`corrections`); это не неизменяемый аудит действий.

### Загрузка и проверки

Набор из basw/handout подключается при старте. Сохранённые отчёты CLI импортируются в историю при совпадении хэшей исходных файлов; они явно обозначены как сохранённые результаты, а не новые проверки.

Кнопка «Загрузить ARB» добавляет отдельный набор: обязательны русский и казахский файлы; английский контекст и глоссарий CSV/JSON необязательны. Максимум 10 МБ файлов через интерфейс и 25000 исходных строк. Колонки глоссария: ru, kk; дополнительно en, note, key и variants (в CSV через |). В текущей версии целевая локаль — kk.

Переводы не меняются. Повторяющиеся ключи сохраняются в диагностике; основной анализ использует последнее значение. Совпадения, длина, варианты терминов и предположения модели не считаются автоматически подтверждёнными ошибками.

Каждый новый запуск работает в отдельном Node worker, поэтому интерфейс доступен во время генерации. Одновременно выполняется один запуск. Остановка прекращает worker и сохраняет уже полученный отчёт. При аварийной остановке сервер помечает ранее выполнявшийся запуск как прерванный; последнее несохранённое обновление может быть потеряно. Запуск автоматически не возобновляется. Кэш позволяет повторить завершённые запросы без генерации.

По умолчанию выбраны кодовые проверки; Qwen включается отдельно. Бюджет относится ко всему запуску, не к каждой строке. Задачи сверх бюджета помечаются как отложенные. Кэшированные ответы бюджет не расходуют. Глоссарий без файла помечается как отсутствующий. Даже если прогресс достиг 100%, отдельные модули могут быть пропущены или отложены — смотрите покрытие.

## Хранение

Загруженные наборы, история, комментарии и журналы находятся в platform/private-data. Кэш модели остаётся в locqa/private-results/cache. Обе папки и basw исключены из Git. Нет внешних шрифтов, аналитики или API: браузер общается с локальным сервером, сервер — с локальной Qwen. Сервер привязан к 127.0.0.1 и не доступен другим устройствам по сети. Проверяются Host, Origin и токен изменяющих запросов.

Это локальная однопользовательская платформа. Авторизации и совместной работы нет. Имя проверяющего в отметках — local_user; отметка означает фактическое нажатие пользователем, а не верификацию квалификации носителя языка.

## Разработка и проверки

Node.js 24; используются уже установленные зависимости locqa. В новом окружении сначала `npm.cmd ci --ignore-scripts --prefix locqa`, затем `node platform/server.mjs`.

```powershell
node --test platform/server.test.mjs platform/recommendations.test.mjs
npm.cmd test --prefix locqa
```

Интеграционные проверки используют отдельные временные данные: загрузка, некорректные ARB, защита API, выполнение реального worker, отмена, запрет параллельного запуска, отметки человека, экранирование HTML и сохранение после перезапуска. Исходные данные конкурса тестами не меняются.

Проверено получение HTML/JS/CSS через HTTP и подключение к Qwen. Визуальная проверка через автоматизированный браузер не выполнена: служба доступа к браузеру была недоступна. Платформа не опубликована в интернете.
