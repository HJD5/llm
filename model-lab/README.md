# Настройка Qwen3-8B для Qazaq Loc QA

Это локальный профиль запросов и лаборатория проверки качества. Веса Qwen3-8B Q4_K_M не изменены, дообучение не выполнялось. Платформа не создавалась. Обычный чат на порту 8088 не получает этот профиль автоматически: используйте команды ниже или передавайте содержимое profile.txt как system message.

## Что настроено

- Инструкция для проверки русско-казахской игровой локализации, 11 категорий задания.
- Учёт переданного глоссария, контекста, имён и брендов; осторожность при неоднозначных строках.
- Требование сохранять плейсхолдеры и ICU; разные языки не обязаны иметь одинаковые категории множественного числа.
- JSON с ограниченной схемой; проверка количества записей, идентификаторов и типов ошибок после генерации.
- Выключенное размышление, temperature 0.2 и фиксированный seed 42. Это исходная настройка для эксперимента, а не доказанно оптимальные параметры. Между запусками возможны отличия даже с фиксированным seed.
- Предложения не применяются автоматически и не помечаются проверенными человеком.

Схема структурированного ответа поддерживается llama.cpp: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#post-v1chatcompletions-openai-compatible-chat-completions-api

## Использование

Запустите модель через start-qwen.cmd в корне проекта. В PowerShell из C:\OSPanel\domains\llm:

```powershell
node model-lab/lab.mjs review model-lab/example.json model-lab/example-result.json
```

Вход: объект с records (от 1 до 12 записей) и необязательным glossary. Каждая запись содержит id, source, target (строка или null), необязательные context и max_chars. Пример структуры есть в example.json. Глоссарий передаётся массивом объектов ru, kk, en, note. Указанные термины должны быть согласованы с носителем; тестовый термин в cases.json нужен только для проверки соблюдения заданного правила.

Выход: output.results с id и issues. В каждой находке type, evidence и suggestion. Это предложения модели, не готовый конкурсный report.json. Источник истины о ручной проверке — человек, а не ответ модели.

Не отправляйте целиком файл на 5500 строк: контекст сервера 4096 токенов. Ограничение входа по байтам — предварительная защита, не точный подсчёт токенов; если сервер сообщает переполнение контекста, уменьшите пакет. Начните с 1–3 коротких строк с нужным контекстом.

## Сравнение

```powershell
node model-lab/lab.mjs evaluate
node model-lab/lab.mjs holdout
node --test model-lab/lab.test.mjs
```

Оба профиля используют одинаковую JSON-схему, параметры генерации, порядок и набор входных данных. Меняется только системная инструкция. Это сравнение специализированной инструкции с краткой базовой, не сравнение с моделью без ограничений формата. Результаты сохраняются с датой в results; фиксируются хэши инструкции и набора, время, usage и ответ.

Ожидаемые метки не передаются модели. Считаются precision/recall по парам (id, тип ошибки), лишние и пропущенные находки, полное совпадение набора меток по строке. Нулевой знаменатель precision обозначен null.

`evaluate` отправляет первый набор целиком. `holdout` сравнивает профили на втором наборе по одной строке; нельзя приписывать разницу между этими двумя наборами только инструкции. Сравнивайте профили внутри одного запуска. Команда `review` также обрабатывает строки по одной; поэтому межстрочная согласованность терминов автоматически не проверяется, нужен дополнительный контекст или отдельная проверка. Первая инструкция сохранена в profile-v1.txt, вторая — в profile-v2.txt. Текущая находится в profile.txt.

## Ограничения оценки

12 синтетических примеров не являются конкурсным тестом, случайной выборкой или доказательством качества казахского перевода. Пять корректных примеров проверяют ложные срабатывания. Семь положительных примеров охватывают 7 из 11 категорий; length_overflow, machine_translation_suspect, inconsistent_term и orthography этим набором не оцениваются. Ожидаемые метки заданы разработчиком, носитель их не проверял.

Инструкция учитывает требования задания, поэтому результаты на близких искусственных примерах могут быть оптимистичными. После первого просмотра результатов этот набор можно использовать только как регрессионный. Для последующих улучшений нужна новая независимая выборка. Один запуск не оценивает стабильность. JSON-схема обеспечивает формат, но не правильность находок, переводов или сохранение ICU в предложении.

## Реальные данные из basw

Добавлен отдельный диагностический путь. Исходные ARB остаются неизменными. Данные и отчёты с их содержимым исключены из Git через .gitignore.

```powershell
python model-lab/audit_data.py
node model-lab/real-check.mjs
python model-lab/summarize_real.py
```

Первый шаг читает четыре основных файла, сохраняет контекст повторяющихся @@comment и варианты повторяющихся ключей. Основной структурный аудит выполняется по последним значениям ключей; все варианты дубликатов требуют отдельной проверки. Проверки не заменяют полноценный ICU-парсер или Flutter.

Второй шаг запускает текущую Qwen только на 12 целевых записях из test_sample, затем три подробных запроса. Это диагностическая выборка для изучения поведения, не полная проверка 5469 казахских ключей. Предварительные замечания errors_ru.md модели не передаются и не используются как полная эталонная разметка. Профиль во время прогона не меняется. Ошибки запросов сохраняются явно.

Третий шаг собирает локальный отчёт в private-results/REPORT.md. Если запустить его до завершения модели, отчёт явно покажет неполные счётчики; после окончания нужно запустить повторно. В этой папке также лежат структурные находки, варианты дубликатов, хэши входных файлов и оригинальные ответы модели.
