# Отдельные проверки Qazaq Loc QA

Локальный CLI с 11 независимыми модулями. Он читает ARB, выдаёт JSON и HTML, не меняет переводы и не обучает модель. Платформа и интерфейс редактирования не создавались.

## Запуск из корня проекта

```powershell
.\locqa.cmd check --source basw/handout/intl_ru.arb --target basw/handout/intl_kk.arb --reference basw/handout/intl_en.arb --out locqa/private-results/report.json
```

По умолчанию запросов к модели нет. Языковые проверки показываются как отложенные, а не успешно пройденные. Создаются report.json и report.html. Отчёты содержат исходные данные кейса; private-results и basw исключены из Git.

Для Qwen сначала запустите start-qwen.cmd. Затем, например, проверьте смысл одной строки:

```powershell
.\locqa.cmd check --source basw/handout/intl_ru.arb --target basw/handout/intl_kk.arb --reference basw/handout/intl_en.arb --checks machine_translation_suspect --keys drag_next_races_after --llm --max-llm-calls 1 --out locqa/private-results/semantic.json
```

Можно указать несколько категорий и ключей через запятую. Общий лимит сетевых запросов по умолчанию 12. После исчерпания лимита остальные задачи отмечаются deferred. Это ограничение общего бюджета, не 12 запросов на каждую строку. Кэшированные результаты не расходуют бюджет. Модель выполняет запросы последовательно, загружается одна копия Qwen.

## Модули

| Файл в src/checks | Метод | Границы проверки |
|---|---|---|
| untranslated.mjs | Код | Отсутствующие, пустые или нестроковые значения |
| same_as_source.mjs | Код | Совпадения RU→KK после нормализации; кандидаты, имена и заимствования требуют исключений |
| placeholder_mismatch.mjs | ICU AST и printf-разбор | Имена аргументов и стандартные printf-подстановки; повторное использование именованного аргумента допустимо |
| plural_mismatch.mjs | ICU-парсер | Синтаксис, other, тип plural/select, offset, явные ветви и допустимые категории целевой локали |
| glossary_violation.mjs | Глоссарий | Точные исходные термины и явно перечисленные варианты; не полноценная морфология |
| length_overflow.mjs | Код | Заданный предел по кодовым точкам Unicode или осторожная эвристика; пиксели не измеряются |
| suffix_harmony.mjs | Код | Только известное окончание непосредственно после {аргумента}; риск зависит от runtime-значений |
| inconsistent_term.mjs | Группировка | Разные варианты одинакового короткого исходника; различия могут быть оправданы контекстом |
| machine_translation_suspect.mjs | Qwen | Отдельная инструкция для смысла и явной грамматической ошибки |
| orthography.mjs | Qwen | Отдельная инструкция для конкретной опечатки; словарь пока не подключён |
| wrong_language.mjs | Qwen | Отдельная инструкция для чужого языка; короткие неоднозначные строки пропускаются |

Проверки могут одновременно находить разные проблемы в одной строке. Наличие критической структурной проблемы откладывает языковой анализ до исправления структуры. В каждой из трёх языковых проверок Qwen получает только конкретную задачу; тип находки присваивает вызывающий модуль. Поэтому модель не может назвать смысловую ошибку suffix_harmony.

Маршрутизация уменьшает ненужные вызовы, но запуск всех трёх языковых модулей на каждой длинной строке всё равно требует до трёх запросов. Ускорение по сравнению с одним общим запросом для языкового анализа не измерялось и не гарантируется. Выбирайте нужные --checks и --keys, используйте кэш.

## Глоссарий и ограничения

`--glossary` принимает JSON-массив или CSV с колонками ru, kk, необязательными en, note, key, variants. В CSV варианты разделяются символом `|`, в JSON задаются массивом. key ограничивает термин конкретным ключом. Глоссарий должен быть согласован с носителем; без файла этот модуль отмечается skipped/no_glossary.

`--config locqa/config.example.json` включает пример настройки. allow_unchanged применяется только когда целевой текст действительно совпадает с исходным. Это не разрешение произвольно менять бренд. В max_chars можно задать реальные лимиты: `{"garage_rent_button": 16}`. Не придумывайте размеры интерфейса для повышения количества находок.

## Контроль ответов Qwen

Модель сначала возвращает цитаты и объяснение, затем clear/error/uncertain. Схема JSON ограничивает форму ответа; цитаты проверяются на точное вхождение. Таймауты, обрезанные ответы, неверные поля и отсутствующие цитаты при error считаются сбоем, а не корректной строкой. По контракту clear требует пустых цитат и отсутствия исправления. Если модель вернула clear с доказательством или исправлением, проверка консервативно переводится в uncertain с сохранением исходного ответа. Это может отклонить и верный ответ с избыточной цитатой. Автоматическая проверка не умеет доказать смысловую согласованность любого объяснения; само наличие цитаты не доказывает правоту модели.

Этот этап запрашивает только обнаружение ошибок, без исправления переводов. Если модель всё же предложит исправление, его структура проверяется, но оно всё равно не применяется автоматически. Все находки Qwen остаются candidate и reviewed_by_human=false. Confidence=null: вероятности не калиброваны, число уверенности не выдумывается.

Кэш зависит от инструкции, схемы, параметров генерации, входной строки, контекста, endpoint и model_revision. При смене модели или адаптера обязательно меняйте model_revision в конфигурации: сервер не сообщает криптографический хэш весов автоматически. По умолчанию указан хэш установленной Qwen3-8B Q4_K_M. Доступ разрешён только к локальному endpoint. Данные во внешние API не отправляются.

## Дубликаты и покрытие

Повторяющиеся @@comment используются как контекст раздела. Для повторяющихся ключей сообщений выбирается последнее значение, но все варианты с номерами строк остаются в diagnostics. Ранние варианты нужно проверять отдельно; их наличие не замалчивается. Нестрочные значения, лишние ключи и ошибки ICU исходника тоже отражаются в диагностике. Исходник с ошибкой нельзя использовать для обвинения перевода.

JSON содержит issues, modules, model_reviews, diagnostics и provenance. В modules отдельно указаны assessed, findings, skipped и причины пропуска, deferred, uncertain, failed. Отключённый или отложенный модуль не означает отсутствие ошибки. Финальный отчёт при сбоях модели сохраняется, команда возвращает ненулевой код. При длительном прогоне промежуточный JSON сохраняется как .partial; успешные запросы сохраняются в кэше.

## Проверки и зависимости

Node.js 24. Установка зависимостей на другом компьютере: `npm.cmd ci --ignore-scripts --prefix locqa`. Тесты: `npm.cmd test --prefix locqa`.

Используются:
- [FormatJS ICU parser](https://formatjs.github.io/docs/icu-messageformat-parser/) для вложенных сообщений;
- [Microsoft jsonc-parser](https://github.com/microsoft/node-jsonc-parser) для дерева свойств и дубликатов (вход дополнительно проверяется строгим JSON.parse);
- [csv-parse](https://csv.js.org/parse/api/sync/) для CSV с экранированными значениями.

Версии зафиксированы package-lock.json. ICU-парсер не является полной заменой Flutter gen-l10n: режим апострофов, метаданные, генерацию Dart и совместимость конкретного Flutter нужно проверять отдельно. Общие ICU ошибки аргументов отображаются в категории plural_mismatch с уточнением причины. printf-разбор поддерживает обычные буквенные спецификаторы и позиционные номера; ширины через `*` и экзотические форматы пока не поддерживаются.

## Что дальше улучшать в модели

Сначала разметить независимые примеры отдельно для трёх языковых задач и проверить precision, recall, ложные тревоги, долю uncertain/сбоев и время. Сравнить короткие инструкции с исходным Colab на одних данных и одном формате. Только после проверки носителем готовить примеры для QLoRA. Не обучаться на собственных неподтверждённых выводах Qwen. Разделение кода и запросов само по себе не улучшает веса или знание казахского.
