# Повторная проверка LLM на Kaggle

Изучен `notebookf469d3adc7.ipynb`, включая ответы модели и FastAPI-адаптер. Frontend не изменялся.

Изменения: отдельные определения и отрицательные примеры для трёх детекторов; `no_issue` без убедительной ошибки; точные цитаты; для чужого языка дополнительные поля `detected_language` и `language_evidence`. Необоснованные находки получают `uncertain` и остаются в `model_reviews` для человека, а не в `issues`. Узкий фильтр отвергает доказательства, состоящие только из известных корректных форм «сыйақыны»/«жеңілдіктермен». Это не полноценный словарь и не доказательство языка всего предложения.

Контракт модели использует `issue`/`no_issue`; отчёт сохраняет совместимые `error`/`clear`. Старые ответы с этими значениями тоже принимаются. Неизвестные поля, типы, отсутствующие обязательные поля и выдуманные цитаты отклоняются. Генерация исправлений отключена; исходные ARB не меняются.

По умолчанию: 768 выходных токенов, один повтор, таймаут 240 секунд на попытку. Повтор расходует `--max-llm-calls`. После начатой, но неудачной проверки исчерпание бюджета означает `failed`; ещё не начатые проверки получают `deferred`. При `finish_reason: length` повтор получает удвоенный лимит, максимум 4096. Настройки JSON: `llm_max_tokens`, `llm_max_retries` (0–2), `llm_timeout_ms`.

В ноутбуке FastAPI игнорирует `response_format`, ограничивает `max_new_tokens` числом 1024 и всегда возвращает `finish_reason: stop`. Поэтому нельзя полагаться на серверную схему или этот флаг. LocQA самостоятельно проверяет JSON. В адаптере стоит возвращать `length`, если генерация исчерпала лимит без EOS; увеличить серверный предел, если нужен повтор с 1536 токенами. Не изменяйте параметры загрузки модели ради этого. В конфигурации укажите настоящий `model_revision` Kaggle-модели вместо хеша локального GGUF: это также часть ключа кеша.

```sh
npm test --prefix locqa
node locqa/evaluate.mjs locqa/test/llm-regression.json locqa/config.example.json reports/llm-regression.json
```

Вторая команда вызывает настоящую модель (до 8 запросов), включая короткий орфографический пример. Четыре примера проверяют регрессии, а не общую точность. Для оценки Precision/Recall подготовьте аналогичный JSON из 30–50 независимо размеченных строк с положительными и отрицательными примерами каждой категории; замените первый путь в команде. Не используйте ответы самой Qwen как эталон. Метрики выводятся по категориям; неопределённые/сбойные положительные случаи считаются пропусками, а отрицательные не засчитываются как верные ответы. Дополнительно выводится coverage.

Автотесты используют подставные ответы и проверяют протокол/защиту, а не знание казахского Qwen. Прохождение тестов не гарантирует исчезновения всех ложных срабатываний на живой модели. Качество обновлённых промптов на Kaggle ещё предстоит измерить.

Коды CLI: `0` — завершено без сбоев запросов (проверяйте deferred и uncertain); `1` — ошибка запуска/входных данных/записи; `2` — отчёты сохранены, но есть failed LLM-проверки. Сбой одной строки не прекращает остальные. JSON и HTML содержат счётчики покрытия, диагностику попыток и модельные ответы. Новые промпты меняют ключ кеша, старые оценки не переиспользуются.
