# Проверка и утверждение глоссария

После LLM-проверки подготовлен отдельный финальный [shortlist для хакатона](SHORTLIST.md): 120 терминов, только `proposed`, без новых вызовов Qwen. Исходные 683 кандидата и все предыдущие результаты сохранены.

## Быстрый отбор для CPU: smart

По умолчанию теперь используется `--selection smart`. Сначала все строки проходят детерминированный предварительный отбор; Qwen получает только выбранную очередь новых терминов. `status` по-прежнему всегда `proposed`, правила и ответы модели не означают одобрения человека.

| Класс предварительного отбора | Значение |
|---|---|
| `rule_checked` | Проверки правил завершены: известное имя, стандартное сокращение, точный дубликат или форматирование. Правильность перевода лингвистически не подтверждена. |
| `needs_llm` | Важная игровая терминология с контекстом, подозрительный перевод, конфликт в уже заданном ключе либо пустой KK с полезным контекстом. |
| `needs_human` | Недостаточно контекста либо разные значения/единицы требуют выбора ключа. Повторный общий вопрос Qwen этого не решает. |
| `low_priority` | Общие UI-фразы, настройки звука/графики, номерные варианты, технические шаблоны и другие слабые кандидаты для компактного глоссария. Они сохраняются в результате. |

Выше в очереди стоят короткие основные игровые термины: оружие, инвентарь, уровень, фракция, клан, валюта и т. п. Дубликаты подавляются только при совпадении исходных метаданных и контекста; разные ключи не объединяются. Отсутствие особых казахских букв не используется как доказательство русского языка. Все строки и исходные метаданные сохраняются.

Сначала оцените нагрузку по существующему результату, не вызывая модель:

```powershell
.\locqa.cmd review-glossary --input .\glossary_draft.csv --out .\locqa\private-results\glossary_review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --resume --selection smart --priority high --limit 18 --max-llm-calls 6 --dry-run
```

`--dry-run` не пишет CSV/контрольную точку/кэш и не делает HTTP-запросов, включая `/tokenize`. Он сообщает распределение классов, число сохранённых результатов, очередь после их исключения, выбранные термины, ожидаемые вызовы и жёсткий лимит. Совпадающие файлы кэша проверяются локально. Оценка вызовов рассчитана без повторов; уменьшение пакета по 4096 токенам и ошибки могут сократить число обработанных терминов в пределах того же бюджета.

Ограниченный запуск после просмотра плана:

```powershell
.\locqa.cmd review-glossary --input .\glossary_draft.csv --out .\locqa\private-results\glossary_review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --resume --selection smart --priority high --limit 18 --max-llm-calls 6
```

Это максимум **6 дополнительных попыток генерации**, включая повторы, а не запуск всего глоссария. Кэш не расходует бюджет и читается до токенизации. Термины сверх бюджета остаются для продолжения. При следующем запуске `smart` берёт следующие подходящие строки, уже завершённые результаты пропускаются.

Чтобы сохранить отдельную ветку результата и исходный CSV, используйте новый `--out` и `--reuse-review`:

```powershell
.\locqa.cmd review-glossary --input .\glossary_draft.csv --out .\locqa\private-results\my-smart-review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --reuse-review .\locqa\private-results\glossary_review.csv --selection smart --priority high --limit 18 --max-llm-calls 6 --dry-run
```

Для исполнения уберите только `--dry-run`. Если `my-smart-review.csv` уже существует, продолжайте его через `--resume`. Подходящая контрольная точка переносит полные завершённые результаты, включая сведения о запросах. Если остался только CSV, завершённые строки повторно проверяются на совпадение оригинала, контекста, известной версии модели и текущих правил. Изменённые/невалидные результаты не считаются завершёнными. Старый CSV без сведений о модели помечается `legacy_csv_revalidated`; он сохраняется как предложение, а не как подтверждение модельной версии или носителя. Статусы одобрения из импортируемого review CSV не переносятся в статус рекомендаций.

Новые параметры:

| Параметр | Значение по умолчанию | Поведение |
|---|---|---|
| `--selection smart\|all` | `smart` | `smart` выбирает очередь по всему черновику; `all` сохраняет прежний режим первых N входных строк. |
| `--priority high\|medium\|all` | `all` | `high` — только высокий; `medium` — высокий и средний; `all` — все приоритеты. |
| `--limit` | `20` | В `smart` максимум новых подходящих строк; в `all` первые N входных строк, включая завершённые. |
| `--max-llm-calls` | `12` | Жёсткий предел новых попыток генерации текущего запуска; повторы включены. |
| `--dry-run` | выключен | Только план без HTTP и записи результатов. |
| `--reuse-review` | не задан | Использовать завершённую работу из другого review CSV и подходящей контрольной точки. |

В CSV добавлены `review_screening_class`, `review_screening_priority`, `review_screening_reasons`, `review_screening_checks`, `review_duplicate_of`, `review_rule_suggestion` и поля происхождения результата. `rule_suggestion`, например `Қазақстан`, является отдельной подсказкой правил. Поле `review_state` сохраняет прежний жизненный цикл Qwen (`pending`, `reviewed`, `deferred`, `failed`, `rules`); классификация отбора хранится отдельно. Поле `translation_linguistically_verified=false` в контрольной точке подчёркивает ограниченность правил.

Статистика классов относится ко всем кандидатам, в том числе уже просмотренным раньше; завершённые результаты учитываются отдельно и не складываются с классами как независимые группы. `unresolved_human` — строки с неразрешённой неоднозначностью/сбоем, а `awaiting_human_approval` — все предложения, ожидающие реального решения человека. Даже правильный `keep` Qwen не является `approved`.

В выполненной CPU-демонстрации распределение 683 кандидатов: 5 `rule_checked`, 334 `low_priority`, 220 `needs_human`, 124 `needs_llm`. Таким образом, 559 кандидатов обходят Qwen в режиме `smart`; это решение об очереди, не подтверждение качества переводов. Из 124 модельных кандидатов 15 уже были просмотрены раньше, поэтому до демонстрации оставалось 109 подходящих строк высокого приоритета. Сохранены все 98 существовавших завершённых результатов, включая те, которые новый отбор относит к другим классам. После dry-run обработаны только 18 новых терминов за 6 дополнительных запросов (лимит 6, с учётом повторов), без сбоев. Всего завершено 116 строк; в очереди осталось 91, неразрешённого решения человеком требуют 226 строк. Все 683 выходные строки остаются `proposed`. Старые рекомендации сохранены без изменения; хэши ARB и черновика совпали. [Отчёт, выбранные термины и статистика](private-results/glossary-smart-demo/REPORT.md), [план dry-run](private-results/glossary-smart-demo/dry-run.json). Результат опубликован в обычный `private-results/glossary_review.csv`; снимок прежнего результата сохранён в `glossary-smart-demo/baseline.csv` и его контрольной точке.

## Изменения после первого теста: версия 2

Структура проекта и исходная схема глоссария сохранены. Промпт сопоставляет RU, KK, EN и ARB-контекст, отделяет смысловую ошибку от стилистического предпочтения и содержит положительные/отрицательные примеры. `профиль` в значении UI Profile сохраняется; каноническое имя страны — `Қазақстан`. Регистр обычных UI-надписей, например `ЖАЛҒАСТЫРУ`, не меняется по этому правилу.

Каждый предложенный KK проверяется в `src/glossary-validation.mjs`: сохранность структуры, узкий список явно русских фрагментов (включая `ножки`), регистр известного имени страны, возможная потеря казахского множественного окончания. Явно обозначенные собственные имена/бренды и стандартные сокращения не считаются ошибкой лишь из-за совпадения с русским. Это ограниченные проверяемые правила, а не полный определитель языка или словарь; прохождение проверок не удостоверяет языковую правильность нового перевода. Непроверенные рекомендации не заменяют исходный `kk` и не становятся `approved`.

Если предложение противоречит правилам, оно переводится в `uncertain`, `recommended_kk` очищается, исходный KK остаётся на месте. В CSV добавлены `review_validation_flags`, `review_rejected_kk`, `review_recommendation_source`, `review_requires_human`, `review_context_groups` и `review_requires_key_scope`. В контрольной точке `model.verdict`, `model.recommended_kk`, `model.reason` показывают ответ модели до применения правил; результаты правил отделены от ответа Qwen. Все выходные строки остаются `proposed`, с `reviewed_by_human=false`.

Разные EN-значения, контекстные варианты и неоднозначные единицы требуют отдельной области действия. Анализируются все найденные ARB-контексты; в пакет выбираются представители разных групп, а не только первые четыре строки. Такие группы не разбиваются и не объединяются автоматически. В платформе для них нужно выбрать **Область решения → конкретный ключ**. Одобрение экспортируется с этим `key` и не разрешает перевод для остальных ключей. В одной исходной строке хранится одно текущее решение для одного ключа; для нескольких отдельных канонических правил подготовьте отдельные строки черновика с явными `key` и проверьте их независимо. Глобальное одобрение конфликтующей группы блокируется сервером, в том числе при прямом запросе API и экспорте старого решения.

Версия контрольной точки изменилась с 1 на 2. Старый результат нельзя продолжить как новый тест: выберите новые пути вывода и пустую папку кэша. Точный свежий повтор первых 20 строк, без `--resume`:

```powershell
.\locqa.cmd review-glossary --selection all --input .\glossary_draft.csv --out .\locqa\private-results\glossary-v2-test\glossary_review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --limit 20 --batch-size 3 --max-llm-calls 14 --timeout-ms 240000 --cache-dir .\locqa\private-results\glossary-v2-test\fresh-cache
```

Команда отказывается перезаписывать результат. Для ещё одного независимого теста используйте новое имя папки вместо `glossary-v2-test`, включая путь к кэшу. Для продолжения уже выполненного теста используйте его контрольную точку с `--resume`; это отличается от свежего теста без кэша.

В выполненном повторном тесте тех же первых 20 строк: 7 запросов Qwen, 0 попаданий в кэш, 0 сбоев. До изменения было 11 `keep`, 4 `change`, 5 `uncertain`; после правил — 11 `keep`, 1 `change` (`Қазақстан`), 8 `uncertain`, из них 7 требуют выбора ключа. Сырые ответы новой Qwen: 12 `keep`, 2 `change`, 6 `uncertain`; правила дополнительно остановили общий перевод единицы `м` и замену текста на тот же текст. Все 683 строки сохранены как `proposed`, 663 пока не проходили языковую проверку. Хэши RU/KK/EN ARB и черновика не изменились. [Полное сравнение 20 строк, включая ответы модели до правил](private-results/glossary-v2-test/BEFORE-AFTER.md). Предыдущие CSV и контрольная точка сохранены в той же папке как `before-full.csv` и `before-full.csv.checkpoint.json`; обычные рабочие пути `private-results/glossary_review.csv` и его контрольная точка обновлены результатом версии 2.

Все команды ниже выполняются в Windows PowerShell из корня `llm-main`. Нужен Node.js 24 и уже установленная локальная Qwen3-8B Q4_K_M. Исходные ARB и `glossary_draft.csv` не изменяются. Внешние AI-сервисы не используются.

## Сначала 20 терминов

```powershell
.\locqa.cmd review-glossary --selection all --input .\glossary_draft.csv --out .\locqa\private-results\glossary_review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --limit 20 --batch-size 3 --max-llm-calls 14 --timeout-ms 240000
```

В примере с `--selection all` число 20 — первые 20 строк черновика, включая непригодные по правилам. Все остальные строки тоже сохраняются в выходном CSV с `review_state=pending`. Это не их языковая проверка. Новый режим по умолчанию `smart` выбирает до 20 новых подходящих строк из всего черновика. Проверки кодом выполняются для всех строк, чтобы замечать дубликаты и конфликты за пределами выбранной очереди.

Создаются:

- `glossary_review.csv`: исходные колонки и дополнительные поля `recommended_kk`, `review_explanation`, `review_priority`, `review_verdict`, `review_state`, `review_flags`, `review_context`, `review_id`.
- `glossary_review.csv.checkpoint.json`: полные исходные строки, контекст, результаты и сведения о запросах. Сохраняется перед первым запросом и после каждого пакета. CSV восстанавливается из контрольной точки при продолжении.
- `locqa/private-results/glossary-cache/`: проверенные структурированные ответы Qwen, включая исходный JSON и сведения о попытках.

В `kk` остаётся исходный текст; предлагаемая замена записывается отдельно. Все строки выходного CSV имеют `status=proposed`, пустой `reviewer` и `reviewed_by_human=false`. Исходные `status`, `reviewer` и любые дополнительные метаданные сохранены в `original_json`; для статуса и имени есть также отдельные `original_status` и `original_reviewer`.

`keep` означает, что Qwen предлагает сохранить существующий перевод, `change` — предлагает замену, `uncertain` — не уверена, `unsuitable` — сомневается в пригодности для общего глоссария. Ни один из этих результатов не является одобрением человека. Если Qwen называет перевод ошибочным, но предлагает тот же текст, результат переводится в `uncertain`.

## Продолжение и полный запуск

Остановить процесс можно `Ctrl+C`: текущий незавершённый пакет останется для следующего запуска. Сохранённые результаты не пропадают. При принудительном завершении используйте последнюю записанную контрольную точку.

Продолжить пробные 20 строк, повторив сбои:

```powershell
.\locqa.cmd review-glossary --selection all --input .\glossary_draft.csv --out .\locqa\private-results\glossary_review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --limit 20 --batch-size 3 --max-llm-calls 14 --timeout-ms 240000 --resume --retry-failed
```

После просмотра пробного результата продолжить до всех 683 терминов:

```powershell
.\locqa.cmd review-glossary --selection all --input .\glossary_draft.csv --out .\locqa\private-results\glossary_review.csv --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --limit 683 --batch-size 3 --max-llm-calls 500 --timeout-ms 240000 --resume --retry-failed
```

Уже проверенные строки и строки, отсеянные правилами, повторно не отправляются. Без `--retry-failed` сбои сохраняются для разбора; `pending` и `deferred` продолжаются автоматически. Изменение черновика, используемого ARB-контекста, версии модели или инструкции требует новых путей вывода. При замене весов укажите новый `--model-revision`.

Параметры (`.\locqa.cmd review-glossary --help`):

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `--limit` | `20` | `smart`: до N новых подходящих строк; `all`: первые N входных строк; до 10000 |
| `--batch-size` | `3` | От 1 до 8 терминов в запросе |
| `--max-llm-calls` | `12` | Лимит попыток генерации на текущий запуск; повторные попытки тоже расходуют лимит |
| `--timeout-ms` | `240000` | Таймаут каждого локального HTTP-запроса |
| `--max-retries` | `1` | Повторы невалидного JSON, обрезанного ответа или ошибки; от 0 до 2 |
| `--max-tokens` | `768` | Бюджет ответа пакета; от 128 до 2048 |
| `--context-tokens` | `4096` | Верхний предел контекста, максимум 4096 |
| `--checkpoint` | `<out>.checkpoint.json` | Путь контрольной точки |
| `--cache-dir` | `locqa/private-results/glossary-cache` | Локальный кэш структурированных ответов |
| `--resume` | выключен | Продолжить контрольную точку с тем же входом |
| `--retry-failed` | выключен | Повторять сбои при продолжении |
| `--rules-only` | выключен | Только правила и создание/вывод контрольной точки, без обращения к модели |

Пакеты выполняются последовательно. Перед генерацией сервер llama.cpp рендерит шаблон через `/apply-template`, затем считает токены через `/tokenize`. Сумма входа, бюджета ответа и запаса 64 токена не превышает заданный контекст. При необходимости пакет уменьшается; слишком большой одиночный термин откладывается. При недоступном токенизаторе генерация не выполняется. Контекст включает до четырёх примеров ARB на термин, число всех найденных контекстов передаётся модели; исходные списки ключей и вариантов сохраняются полностью. Кэшированные результаты не расходуют лимит генерации. На CPU полный запуск может занять значительное время.

Дубликаты не удаляются. Конфликты вариантов — повод посмотреть контекст, а не доказанная ошибка: разные ключи могут обозначать разные смыслы. Сходство русского и казахского написания не считается ошибкой правилами. Qwen получает требования сохранять правильные буквальные переводы, учитывать игровую терминологию и воздерживаться от ответа при неопределённости. Эти инструкции и проверка JSON не гарантируют языковую точность.

Коды завершения: `0` — запуск завершён без строк `failed` в выбранной области (проверьте `deferred`, `pending`, `uncertain`), `1` — ошибка команды/входа/файлов, `2` — результаты сохранены, но есть сбои Qwen, `130` — остановлено сигналом с сохранением прогресса. Статистика `model_calls` и `cache_hits` относится к текущему запуску команды.

## Пакетное решение человеком и экспорт glossary.csv

```powershell
.\start-platform.cmd
Start-Process http://127.0.0.1:8090
```

Если платформа была запущена до обновления кода, перезапустите её через `.\stop-platform.cmd` и `.\start-platform.cmd`, затем обновите страницу.

1. Откройте раздел **Глоссарий** и нажмите **Импорт review CSV**. Выберите `locqa\private-results\glossary_review.csv`.
2. Используйте фильтры статуса/приоритета, поиск и раскрываемый ARB-контекст. Посмотрите исходный KK, предложение и объяснение. При необходимости отредактируйте KK в таблице.
3. Отметьте строки (можно всю страницу), при разных контекстах выберите конкретный ключ в **Область решения**, укажите своё имя и поставьте отметку явного подтверждения. Нажмите **Одобрить выбранные** или **Отклонить выбранные**. Один пакет — до 100 строк. Решение можно отменить через **Вернуть в ожидание**. Изменение текста или ключа снимает отметку подтверждения.
4. Нажмите **Экспорт glossary.csv**. Скачивается CSV в исходной схеме `ru,kk,en,comment,status,key,category,variants,observed_variants,related_keys,reviewer`, содержащий только явно одобренные человеком строки. До первого одобрения экспорт содержит только заголовок. Наблюдённые варианты не превращаются автоматически в разрешённые `variants`.
5. Сохраните скачанный файл, например в корень проекта, и загрузите его вместе с ARB через **Загрузить ARB** для нового набора платформы. Можно также использовать CLI:

```powershell
.\locqa.cmd check --source .\intl_ru.arb --target .\intl_kk.arb --reference .\intl_en.arb --glossary .\glossary.csv --checks glossary_violation --out .\locqa\private-results\glossary-check.json
```

Решения сохраняются в `platform/private-data/glossary-review.json`, включая имя, время, комментарий и историю. Это локальная однопользовательская платформа; имя вводится человеком, квалификация носителя языка не удостоверяется. Повторный импорт сохраняет только решения по полностью совпадающим предложениям и исходным данным; изменившиеся предложения возвращаются в ожидание. CSV не может импортировать автоматические одобрения. Устаревшая версия списка и конфликтующие одобрения одинакового RU с пересекающимися `key` блокируются до исправления, весь пакет отклоняется без частичного сохранения.

## Тесты

```powershell
npm.cmd test --prefix locqa
node --test platform/*.test.mjs model-lab/lab.test.mjs
```

Тесты проверяют правила, сохранность CSV и метаданных, размер пакетов, бюджет контекста, JSON/ID/структуру перевода, таймауты/кэш/лимиты, продолжение, явное решение человеком, защиту API, конфликты, повторный импорт и экспорт в существующий checker. Тесты с подставным транспортом не измеряют языковое качество Qwen; для этого нужен отдельный пробный запуск и ручная проверка.
