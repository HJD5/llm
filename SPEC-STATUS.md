# ТЗ и текущий объём работ

Источник: предоставленный пользователем `Qazaq_Loc_QA_Technical_Specification.docx`, версия 1.0. Сопоставление выполнено 2026-10-31. Это рабочая карта требований, а не заявление о завершённой реализации.

## Принятый объём

- Основной сценарий: русский оригинал → проверка казахского перевода. Английский — дополнительный контекст.
- По прямому указанию пользователя Uzbek QA сейчас исключён. Обнаружение узбекской фразы внутри казахского файла остаётся частью `wrong_language`: это проверка KK, а не поддержка локали UZ.
- Сохраняем Qwen3-8B и существующее ядро Node.js. Python/FastAPI/Typer, React и Qwen3-4B в документе обозначены как рекомендуемый стек, поэтому переписывание проекта не требуется.
- Модель предлагает, человек подтверждает исправление. Исходные файлы не перезаписываются.
- Латиница, командная работа, Translation Memory и GitHub Action не входят в ближайшую обязательную работу.

## Соответствие текущего проекта

| Требование | Состояние и оставшаяся работа |
| --- | --- |
| ARB, ключи, метаданные, дубликаты | Реализовано. При экспорте исправления неоднозначного дублирующегося ключа требуется разрешить дубликаты. |
| 11 категорий | Все модули существуют. Это не означает подтверждённую полноту или точность детекции. Языковые проверки, глоссарий и терминология требуют оценки и расширения. |
| Qwen и устойчивость ответов | Есть раздельные промпты, валидация, повтор, failed/deferred и кеш. Качество на новой размеченной выборке ещё не измерено. |
| AI-рекомендации | В веб-интерфейсе: один вариант с объяснением, структурная проверка и явное подтверждение. Нет ручного редактирования предложения и соседних строк в контексте. |
| Human Review | Есть подтверждение/отклонение находки и отдельное подтверждение/отклонение исправления, время и local_user. Нет всех статусов ТЗ, именованных проверяющих и подтверждения квалификации носителя. |
| reviewed_by_human | В исправленном ARB выставляется после одобрения исправления. В находках сейчас означает решение о находке, включая ложную тревогу. Нужно явно разделить эти значения в согласованной схеме отчёта. |
| Глоссарий | Импорт ru/kk и вариантов есть. Нужны совместимость с term_ru/term_kk/term_en, утверждение терминов, CRUD, категории и экспорт CSV. Утверждённый глоссарий нельзя подменять предположениями модели. |
| JSON / HTML | Формируются. Рекомендации веб-платформы сохраняются отдельно в corrections; нужно согласовать suggestion, статусы и экспорт отчётов. HTML-файл пока без интерактивных фильтров. |
| severity / confidence | severity есть. confidence=null, поскольку уверенность не откалибрована; нельзя заменять её выдуманными процентами. Нужны описание политики и измерения. |
| Исправленный ARB | Веб-экспорт одобренных исправлений есть: intl_kk.reviewed.arb. Требуются согласованное имя intl_kk_fixed.arb и CLI-экспорт по сохранённым решениям человека. |
| CLI | Анализ и отчёты есть, AI включается явно через --llm. Пока нет полного пути импорта решений человека и экспорта исправленного ARB. Самостоятельное одобрение CLI недопустимо. |
| Flutter | Есть проверки структуры ICU/аргументов/тегов; реальный flutter gen-l10n ещё не выполнен. |
| Dashboard | Есть строки, модули, запуск, история, фильтры и подробности. Нет сравнения запусков, полной аналитики принятых рекомендаций и всех фильтров ТЗ. |
| Методология и оценка | Есть технические README и регрессионный runner. Нужны methodology.md, размеченный набор, Precision/Recall по категориям и фактический объём проверки носителем. |

## Очерёдность дальнейшей реализации

Обновление после реализации Human Review: добавлены ручное редактирование, имя и комментарий проверяющего, история версий и повторная проверка структуры. Сохранение правки снимает одобрение; подтверждение привязано к версии и точному тексту. Веб-экспорт теперь называется `intl_kk_fixed.arb`. Эти изменения закрывают соответствующую часть пробелов таблицы выше. Интеграционные тесты прошли. Добавлен `verify-flutter.ps1`; фактический gen-l10n пока заблокирован отсутствием Flutter SDK в PATH. CLI-импорт решений и остальные пункты остаются следующими задачами.

1. Согласовать модель статусов находки и исправления; добавить ручное редактирование, комментарий и имя проверяющего с повторной проверкой структуры.
2. Сделать единый экспорт JSON/HTML/intl_kk_fixed.arb и CLI-импорт подтверждённых решений с привязкой к хешам исходников.
3. Проверить экспорт в минимальном Flutter-проекте командой gen-l10n, включая ICU и метаданные.
4. Доработать импорт, утверждение и экспорт глоссария по полям ТЗ.
5. Оценить Qwen на 30–50 размеченных строках, затем расширять выборку; записать реальные метрики и методологию. Автотесты с подставными ответами не измеряют знание казахского.
6. Дополнить аналитику и фильтры Dashboard после проверки обязательного ядра.

Описанные в документе ограничения данных учитываются как условия проекта. Сам документ не является разрешением публиковать или удалять файлы; такие действия здесь не выполнялись.
